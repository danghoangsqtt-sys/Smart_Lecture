# T-1101 — Game telemetry trong phiên dạy

## Objective

Make a game launched inside the Teaching Mode dock a durable, class-correct activity in the active teaching log, then expose readable game titles in the post-lesson summary.

## Paths

- `web/src/pages/GamesPage.tsx`
- `web/src/pages/TeachingModePage.tsx`
- `server/src/routes/teachingLogs.routes.ts`
- `scripts/e2e-regressions.mjs`
- `.DHSYSTEM/phases/P11-game-teaching-telemetry/PHASE-STATE.md`

## File-Level Plan

- Add an optional launch callback and fixed-class mode to `GamesPage`; the embedded dock reports only a successfully created game session and cannot switch its target class.
- Wire `TeachingModePage` to persist the real game session ID after a launch; opening the dock alone is not telemetry.
- Resolve recorded IDs against `game_sessions` in the class/subject summary and return safe, readable game activity rows.
- Extend the isolated regression flow to verify a stored game session is summarized correctly and unauthorized users remain denied.

## Best-practice checklist

- Preserve the standalone Games page behavior by making new props optional.
- Treat the server as the authorization boundary; only return games whose class and selected subject context match the teaching summary.
- Keep telemetry idempotent through the existing action endpoint and avoid collecting player-private result data.
- Use strict TypeScript interfaces and cover the API contract in E2E.

## Acceptance Criteria

- Teaching Mode persists the ID of an actual newly created or launched saved game, not a dock marker.
- A dock embedded in a class cannot create or launch a game for another class.
- Insights show readable game activity for the class/subject and do not leak games from another context.
- Root typecheck, isolated E2E and clean web build pass.
