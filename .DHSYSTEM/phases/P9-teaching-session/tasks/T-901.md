# T-901 — Teaching Session v1

## Objective

Turn Teaching Mode into a durable, teacher-led session: start or resume a session for the selected curriculum item, record teaching actions, link attendance, then close the session with a compact summary and notes.

## Paths

- `server/src/routes/teachingLogs.routes.ts`
- `web/src/pages/TeachingModePage.tsx`
- `scripts/e2e-regressions.mjs`
- `.DHSYSTEM/phases/P9-teaching-session/PHASE-STATE.md`
- `.DHSYSTEM/TRACKER.md`
- `.DHSYSTEM/ROADMAP.md`
- `.DHSYSTEM/HANDOFF.json`
- `CHANGELOG.md`

## File-Level Plan

- `server/src/routes/teachingLogs.routes.ts`: validate all foreign references against the class; expose a teacher-only active-session lookup; prevent duplicate active sessions for one class; add a validated action endpoint that appends material/game identifiers and updates the attendance linkage.
- `web/src/pages/TeachingModePage.tsx`: load/resume the active session, start a session from the selected item, record mode/game/attendance actions, finish with notes, and show a persistent session-status strip.
- `scripts/e2e-regressions.mjs`: verify session lifecycle, cross-class rejection and action persistence in the isolated database.

## Best-Practice Checklist

- Keep all authorization server-side and class-scoped.
- Use explicit PATCH semantics so `null` is preserved deliberately.
- Make lifecycle operations idempotent where refresh/retry is expected.
- Avoid duplicating existing attendance and game mechanisms; record their IDs/labels in the existing `teaching_logs` table.
- Verify server and web TypeScript plus full isolated E2E before marking done.

## Acceptance Criteria

- A teacher can start one active session per class, refresh the page and resume it.
- Invalid curriculum, lesson-plan or attendance references are rejected when they do not belong to the class.
- Content and game actions are persisted in the teaching log.
- Ending a session persists an end time and notes.
- Existing attendance/game flows remain unchanged and the complete E2E suite passes.
