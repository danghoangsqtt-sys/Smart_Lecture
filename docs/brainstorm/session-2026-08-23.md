## 1. Tầm nhìn sản phẩm (một câu)

Hệ thống LMS **client-server chạy nội bộ trên máy giáo viên**: GV mở phần mềm → học viên truy cập qua WiFi/LAN bằng browser trên điện thoại/máy tính → đăng nhập tài khoản do GV tạo → học bài giảng, làm kiểm tra, chơi game realtime; toàn bộ dữ liệu nằm trên máy GV, hoạt động offline hoàn toàn.

## 3. Mô hình người dùng & quyền

```

             ngân hàng câu hỏi dùng chung (is_public_bank)
Giáo viên  ─ tạo/quản lý lớp đảm nhiệm + TK học viên của mình,
             upload bài giảng/tài liệu/video, ngân hàng câu hỏi riêng,
             soạn đề, host game, sổ điểm + điểm danh

             tự học, tham gia game realtime
```

## 4. Bản đồ tính năng

### Phase 1 — Nền tảng + Trái tim sản phẩm
1. **Auth & tổ chức**: JWT session + bcrypt; GV tạo TK HV (đơn lẻ + import Excel); quản lý lớp theo GV đảm nhiệm
2. **Thư viện bài giảng**: cấu trúc môn → chương → bài; upload PDF/DOCX/PPTX/video; stream video HTTP Range; HV xem qua LAN
3. **Ngân hàng câu hỏi** (kế thừa bluebee): CRUD TN/TL, thư mục, filter Bloom, bulk ops throttle 300ms
4. **Sinh câu hỏi AI**: ma trận Bloom 6 mức, responseSchema JSON nguyên văn từ bluebee, review-before-save workflow, prompt QUY TẮC CỤNG chống bịa
5. **Soạn đề + thi online**: generateExamPaper (originalIndex tracking), attempt state-machine (in_progress→disconnected→submitted), autosave 5s, resume, anti-cheat visibilitychange; chấm TL bằng AI (score 0–10 + feedback)
6. **Games realtime Phase 1**: Socket.IO phòng game; random picker bốc 1–2 HV ngẫu nhiên; trắc nghiệm nhanh Kahoot-style (game đầu tiên)
7. **Sổ điểm & điểm danh**: 3 cột điểm cố định (KTTX | Quá trình 1 | KT kết thúc môn); điểm game/thi chảy vào cột sau khi GV duyệt; buổi học + số tiết vắng + lý do vắng

### Phase 2 — Trí tuệ & đa dạng hóa
8. RAG đầy đủ + chatbot trợ giảng cho GV (trích dẫn nguồn + trang)
9. Game mở rộng: kéo co (đội), đua toán, điền chỗ trống, mô phỏng — dùng chung game engine + question bank
10. Thống kê Azota-style: phổ điểm, phân tích câu sai, xuất Excel 3 sheet, nhận xét AI từng HV
11. Docling sidecar (MIT) cho PDF scan/bảng phức tạp
12. Tính năng khác sẽ bổ sung theo brainstorm tiếp theo ("cùng nhiều tính năng khác")

## 5. Stack kỹ thuật đề xuất

| Lớp | Công nghệ | Ghi chú |
|---|---|---|
| Server | Node.js + Express + better-sqlite3 (WAL) | SQL query whitelist trong server, KHÔNG raw SQL từ client (bài học DTS-LMS) |
| Realtime | Socket.IO | Phòng game, giám thị live, bảng điểm live |
| Frontend | React 19 + Vite + Tailwind build-time | Bỏ Tailwind CDN (bài học esafe-v3) |
| State | Zustand hoặc Context per-domain | Khắc phục props drilling App.tsx ~850 dòng của bluebee |
| Auth | JWT + bcryptjs, role-based middleware | Admin ops chạy trong server process |
| AI | @google/genai + resilience layer bluebee | Queue gap 1800ms, retry backoff+jitter, fallback chain flash→flash-lite→2.0-flash, structured output |
| Storage media | Filesystem `data/media/` + metadata SQLite | Không Base64 trong DB (bài học DTS-LMS) |
| RAG | Chunk heading-aware → text-embedding-001/004 → sqlite-vec hoặc cosine in-memory | Học thiết kế Chunkr: segment type, metadata trang, summary bảng/hình |

## 6. Kế thừa cụ thể từ các dự án anh em

### Copy nguyên văn / thích ứng nhẹ (từ bluebee_LMS)
- `responseSchema` sinh câu hỏi AI + prompt wrapper "chuyên gia sư phạm / QUY TẮC CỤNG / trả [] nếu thiếu"
- Vòng lặp sinh đề chia lô theo ma trận Bloom (mỗi mức 1 request, sleep giữa batch)
- `generateExamPaper` với originalIndex tracking + strip prefix regex `/^([A-F])([\.\:\)])\s+/i`
- ExamResult attempt state-machine + remainingTime resume + redFlags
- AI resilience layer (fallback/backoff/queue/truncate context)
- Excel export 3 sheet SheetJS; prefix `temp_` cho ID chưa commit

### Từ esafe-electro-v3
- RAG pipeline client (`documentProcessor.ts`): chunkText 1000/200, embedChunks retry backoff 429, cosine similarity thuần JS + fallback keyword
- `useSpeechRecognition` hook production-grade (nếu sau này thêm vấn đáp)
- Boot resilience pattern (splash + watchdog + panic screen + ErrorBoundary)
- Game hub pattern: lobby → mode engine → shared SummaryReview
- Template in A4 chuẩn thể thức VN

### Từ DTS-LMS
- IPC/service layer tách biệt (ở đây chuyển thành REST API layer duy nhất)
- Exam engine thuần function dễ test; parser đề text Việt Nam (Mau-*.txt)
- Văn hóa session log bug C/H/M/L + verification `tsc --noEmit`

### Chống lặp lại lỗi cũ (bắt buộc tuân thủ)
1. ❌ Server/API key lộ phía client (C-01 bluebee) → mọi ops đặc quyền chạy trong server
2. ❌ Metadata JSON string gây filter client-side → folder/category/bloom là **cột riêng có index**
3. ❌ TS non-strict + any → bật `strict: true` từ ngày đầu
4. ❌ localStorage làm DB chính → SQLite là source-of-truth duy nhất
5. ❌ File Base64 trong DB → filesystem + đường dẫn
6. ❌ Dead code tích tụ → xoá ngay khi thay thế
7. ❌ Electron nodeIntegration:true/webSecurity:false → không dùng Electron ở GĐ này
